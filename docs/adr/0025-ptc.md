# PTC：程序化工具调用

原生呈现下，模型每步发一个 JSON-schema `tool-call`、每个中间 `tool-result` 都回灌 context；PTC 决策当时的分发还是串行（并行调度已在 ADR 0026 落地）。多步工具工作因此 token 重且难以组合，循环、分支、扇出和结果后处理要么多次模型往返、要么无从表达。决定把 code mode 做成 `ToolRuntime` 的一等呈现模式：`mode: 'ptc'` 时注册表只贡献 `run_code` 传输和一份生成的 SDK `.d.ts`，模型写可擦除 TypeScript 程序、用 `await tools.name(args)` 调用工具，执行落在 capability seam `ctx.ptcRuntime` 后面的 Node provider 上，每个程序是一个在调用方会话 sandbox 策略下运行的托管进程；默认执行模式无状态，另有可选的进程内执行模式提供一次性跨调用内存，不恢复对象、重启后不重放程序。换来的是工具组合能力与被模型主动收敛的 context，代价是一份可能和原生 schema 一样大的稳定 SDK 前缀、一条新的沙箱执行路径，以及程序之间没有持久状态——跨调用状态会脱离 session log，破坏「请求是 log 的纯函数」这一保证；原生单次调用仍是常见路径，所以默认保持 `'native'`，PTC 按部署切换。
