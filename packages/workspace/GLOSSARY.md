# 工作区（workspace）

这个上下文把用户工作过的目录记成持久工作区：稳定 id、规范路径、展示标题，以及一份有序的会话账目。它存在的理由是让宿主产品按目录长期分组会话，同时对模型完全不可见——没有工具、提示词和会话事件。

## Language

### 工作区实体

**Workspace**：一条持久记录，把一个稳定 id 绑定到某个既有目录，带展示标题，并按手工顺序持有属于它的会话。消费者只看到这个接口，它不对模型暴露。

_Avoid_: project

**WorkspaceId**：工作区记录的稳定标识，由生成的 uuid 承载而不是路径；引用锚点用它，路径规范化改写路径时它不受影响。

**canonical path**：工作区拥有的目录身份，尾斜杠、`..` 与符号链接都已解析。路径的唯一性就是规范路径的字符串相等，因此指向已拥有目录的符号链接会碰撞。

_Avoid_: fully qualified path

**display title**：工作区的展示名，创建时默认取路径末段（文件系统根用它自己的写法），跨工作区允许重名。

**workspace status**：工作区目录当前可用性的一次即时判定：`ok`（目录存在）或 `missing-dir`（目录不存在）。目录缺失从不改写记录，因为它可能只是被临时移走。

### 会话归属

**workspace account**：工作区持有的、按手工顺序排列的会话清单（`sessionIds`），是「哪些会话属于它」的唯一真相；归属从不从会话目录反推。

_Avoid_: Session accounting

**membership**：一条会话进入工作区账户的资格：它创建时记录下来的目录必须解析到与该工作区的规范路径相同的现存目录。已入账的候选在目录缺失或符号链接悬空时保留资格，新建会话不享受这个例外。

**Ungrouped**：不属于任何工作区的会话所处的状态，既包括首次启动时没有目录的旧会话，也包括工作区注册被删除之后的会话。

### 列表与初始化

**registry order**：注册表全局持有的工作区 id 有序列表，是工作区展示顺序的权威来源；调整顺序是 DOM-insertBefore 式的移动，而不是排序。

**default Workspace**：首次使用时自动创建的那一个工作区，目录名固定为 `default-workspace`，初始标题取请求目录的末段。它的身份一次提交后复用，删除这条注册也就永久关闭了自动创建。

_Avoid_: initial workspace

**history bootstrap**：首次成功启动时把既有会话按目录归拢成工作区的那一次性初始化；它只读已持久化的会话头、不读事件正文，此后新会话不会再被自动归拢。

### 归档、钉住与准入

**pin**：注册表全局的已钉住会话集合，最近钉住的排在前面，用来把会话排到未钉住会话之前。只有已知且未归档的会话可以被钉住。

**archive**：注册表全局的已归档会话集合，把会话从工作区的分组界面隐藏，而不删除它的会话记录或它在工作区账户里的位置。

_Avoid_: hide

**archive admission**：归档之前对「这个会话还有什么在跑」的判定：任一 provider 报告活动就拒绝归档，除非调用方要求先停掉这些工作。

**SessionActivityKind**：归档准入中「哪一类工作还活着」的分类键，由各 provider 各自合并进一张可扩展映射。工作区包本身不声明任何键，已发布的是 turn、job、subagent、schedule。
